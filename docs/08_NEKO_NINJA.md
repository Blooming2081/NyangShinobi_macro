# 네코 닌자 뽑기 모드 — v0.1

## 소스 기준
`run_gui.py`: `detect_neko_ninja_summon()`(제목·10회 버튼·뽑기 탭), `detect_neko_ninja_result()`(제목·계속 안내), `neko_ninja_summon_loop()`(상태에 따른 1회 탭 반복). 원본 발췌는 `reference/legacy_v206_methods/`.

## 전제 / 범위
- **일반 임무·거울과 분리된 실행 모드 `neko_ninja`**. 사용자가 게임에서 뽑기 화면을 미리 열어놓고 명시적으로 시작한다. 자동 이동/게임 재시작/재화 충전은 없다.
- 게임 재화를 소비하는 **10회 뽑기**이므로 시작 UI에 주의를 표시하고 실행 중 즉시 중지 가능해야 한다. 기본은 기존 소스처럼 수동 중지까지 반복(`maxTenPullCycles=0`). 사용자가 한도를 지정하면 해당 횟수 뒤 멈추도록 할 수 있다.
- 예상하지 못한 팝업이나 화면에서 입력하지 않는다. 진입 상태가 불명확하면 `NeedsUserAction`.

## 원본 화면 판별 (480x1320 기준)
| 상태 | 파일 | 비교 영역 [x1,y1,x2,y2] | 기준 후보 |
|---|---|---|---|
| 뽑기 화면 | `neko_ninja_summon.png` | [34,140,230,186], [252,1136,360,1190], [399,1250,473,1315] | 각각 `TM_CCOEFF_NORMED>=0.90`, 픽셀 평균 오차<=25; 최솟값으로 판정 |
| 결과 화면 | `neko_ninja_result.png` | [34,140,230,186], [170,970,312,994] | 각각 `TM_CCOEFF_NORMED>=0.90`, 픽셀 평균 오차<=20; 전부 충족 |

- 원본은 전체 화면 참고 이미지를 480x1320으로 맞춘 다음 해당 영역끼리 비교한다. 캐릭터 애니메이션 영역은 제외한다. `neko_ninja_summon.png` 전체를 버튼 템플릿으로 검색하지 않는다.
- 인식 기준값은 소스에서 가져온 값이며 실기 검증 전 확정 성능 수치가 아니다.

## 단계 및 입력
```text
N01  뽑기 화면 3 ROI 확인?  → N02
     아니면 결과 화면 2 ROI 확인? → N03
     둘 다 아니면 무클릭/사용자 확인
N02  10회 뽑기 버튼: (305/480, 1164/1320) 1회 터치
     → 0.5초 후 프레임 확인 → N01 (다음 단계 검증 중 재탭 금지)
N03  결과의 계속하기: 동일 정규화 좌표 1회 터치
     → 0.5초 후 프레임 확인 → N01
```
- 원본과 동일한 좌표에서 두 화면을 구분해 버튼을 누른다. 화면별 분기를 반드시 따로 둔다.
- 원본에는 50ms 루프가 있으나 **v0.1은 3초 기본 관측 및 터치 후 500ms 첫 확인**을 우선 적용한다. 애니메이션/전환 과정에서 화면이 그대로인 경우에도 입력을 연속으로 보내지 않는다.
- 중지 버튼은 모드의 어떤 단계에서든 추가 터치를 막아야 한다.

## 코덱스 테스트
`V01-N01` ~ `V01-N05`: 뽑기/결과/미확인 화면/중지/한도/중복 탭 방지. 실기 검증은 MuMu 및 BlueStacks 양쪽에서 수행한다.
