# Architecture Decision Records (ADR) — v0.1

| ADR | 결정 | 채택 사유 | 재검토 조건 |
|---|---|---|---|
| 001 | Windows 10/11 x64, C# + WPF + .NET 10 LTS | UI/엔진 단일 개발언어, Windows 배포 | OS 지원 범위 변경 요청 |
| 002 | 이미지 인식 `IVisionEngine` 뒤 OpenCvSharp5 | 네이티브 OpenCV 사용, 낮은 복잡도 | 측정에서 Vision 자체 병목 확인 |
| 003 | ADB PNG 캡처부터, RAW는 후보 | 우선 호환성/측정 | RAW가 CPU/지연/안정성에서 우월할 때 |
| 004 | adb.exe + input tap, 지속형 Shell은 후보 | 호환성, 최소 의존성 | 반복 명령 실행 지연이 실제 병목일 때 |
| 005 | 기능은 `Features` 안의 모듈별 폴더 | 현업급 경계와 적당한 프로젝트 수 균형 | 기능 단위의 빌드·의존성 필요가 입증될 때 |
| 006 | 이벤트는 JSON(안전한 1~8단계) 또는 컴파일된 C# 핸들러 | 기능 확장/삭제 용이, 스크립트 임의 실행 방지 | 복잡한 이벤트가 잦아 검증 체계가 확대될 때 |
| 007 | 날짜 변경 정상 흐름은 포함, 게임/ADB/OS 재시작 제외 | v2.0.6의 게임 진행 순서 유지 | 별도 복구 기능 승인 시 |
| 008 | 각 장치 단일 Capture/Input 오케스트레이터 | 중복 촬영/입력과 CPU 낭비 방지 | 다중 장치 병렬 구동 요구 시 |
| 009 | `image6.PNG` 단독 완료 확정 금지 | 템플릿 의미가 모호 | 실기 이미지 + 독립적인 완료 증거 확보 시 |

## C# 이벤트 '플러그인' 범위 고지

- **지원:** 저장소 안에 새 C# 이벤트 핸들러 파일 추가 + DI 등록, 독립 테스트. 배포할 때 앱 재빌드.
- **지원:** 단순 팝업 이벤트는 검증된 JSON/이미지 추가만으로 동작 (앱 재빌드 불필요하도록 로더 설계, 배포/설정 갱신 필요).
- **미지원:** 인터넷에서 DLL을 내려받아 프로세스 안에 동적 로드/언로드하는 plugin host, 사용자 임의 스크립트.

## 업무 범위 변경 이력

- 이전 v0.1 패키지에서 '날짜 변경 팝업 자동 처리 제외'는 이번 요구에 따라 **포함으로 변경**.
- 광고 2배 보상, 네코 닌자 뽑기 포함은 유지.
- 복구/스톨 감시/Watchdog/OS 및 게임 재시작 제외는 유지.
