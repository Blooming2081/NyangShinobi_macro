# 날짜 변경 정상 흐름 — v2.0.6 보존 + 이벤트 확장

**v0.1 범위 포함.** 날짜 변경은 정체 복구·게임 재시작 기능과 별개로 **실제 게임 화면에 나타나는 정상적인 UI 흐름**이다.

## 원본 소스/자산 근거

- `run_gui.py`: `handle_date_changed_popup` 7532~7587, `wait_for_home_refresh_after_date_change` 7588~7668, `apply_weekday_mirror_schedule` 1430~1454.
- `assets/images_nav/date_changed.png`: 날짜 변경 팝업 이미지, 원본 후보 임계값 **0.78**.
- `assets/images_nav/date_change_followup_close.png`: 후속 일일 팝업 닫기, 원본 후보 임계값 **0.82**.
- 확인 버튼 좌표 480x1320 기준 **(240,769)**. 후속 닫기 기준 **(440,49)**, 위치 허용 ±(20,20). 실제 게임 해상도에 맞춰 정규화.
- 게임 날짜는 Windows 로컬 시각 기준 `현재 시각 - 4시간`의 날짜. 요일은 Python weekday와 동일하게 **월요일=0 … 일요일=6**를 `mirror.weekdaySchedule`에서 조회한다.
- 원본의 날짜 팝업 중복 클릭 방지 2초, 홈 확인 연속 2회, 원본 홈 대기 한도 60초를 설계 후보로 유지.

## 상태 전환 D01~D07

```text
[모든 모드가 공유한 프레임]
 D01 날짜 변경 팝업 `date_changed` 검출 → 현재 모드 입력 보류
 D02 팝업 확인 1회 터치 → 0.5초 뒤 팝업 닫힘 검증 / 2초 dedupe
 D03 현지 시각 - 4h → 게임 날짜·요일표 갱신 (요일 자동 ON에만 거울 선택 변경)
 D04 홈 갱신 대기 → `date_change_followup_close`가 명확하면 닫기
 D05 홈 화면을 가릴 수 있는 `AfterDateChange` 이벤트를 관측/처리
 D06 팝업 처리가 끝난 뒤 홈 화면 준비 2프레임 연속 확인 (최대 60초)
 D07 이벤트 처리 완료 후 현재 모드 재진입
     - mission: 기존 임무 설정으로 홈→임무→프리셋…
     - mirror: 새 요일 속성/캐릭터 적용 후 홈→거울→입장…
     - neko_ninja: 자동 뽑기 화면 복귀 불가 → NeedsUserAction
```

**v2.0.6과의 의도적 차이:** 원본의 `DateChangedRestart` 예외는 워커 루프를 재진입시키는 방법이었으며, v0.1에서는 `DateChangeFlow`의 상태 전환 결과를 `FlowCoordinator`에 전달한다. 기능 목적(팝업 해제→홈 안정화→새 요일로 재진입)은 같다. 다만 원본의 화면 미확인 상태에서 일반 좌표를 무작정 누르거나 게임 재시작을 시도하는 단계는 v0.1에서 제외한다.

## 이벤트가 추가될 때

예: 04:00 변경 팝업 확인 후 일일 공지 대신 **기간 한정 이벤트 팝업**이 등장하는 경우.

- 날짜 변경 `D01~D04`는 그대로 두고, `D05`에서 신규 이벤트를 검사한다.
- `AfterDateChange`로 등록된 이벤트 핸들러만 해당 화면을 판단한다. 이벤트가 홈 화면을 가릴 수 있으므로 **홈 안정화보다 먼저** 검사한다.
- 닫기 버튼과 다음 화면이 검증되면 `D07`에서 거울/임무 기존 설정으로 복귀한다.
- 인식되지 않은 이벤트 화면이면 임의로 닫지 않고 NeedsUserAction.
- 종전 '날짜 변경 후 일일 팝업 닫기' 이미지는 이벤트 모듈에 복제하지 않고 `DateChangeFlow`가 직접 소유한다.

## 구현 수용 조건

- 임무/거울 어느 단계에서든 날짜 팝업이 명확하면 기존 단계의 불필요한 입력이 중단된다.
- 팝업 터치 후 500ms에 미확인 상태면 무작정 재터치하지 않는다.
- 03:59에는 전날로, 04:00에는 당일로 계산되는 날짜·요일 단위 테스트를 작성한다.
- `mirror.weekdayAuto=false`인 경우 선택한 거울 속성/캐릭터가 날짜 변경에 의해 바뀌지 않는다.
- 날짜 변경 직후 새 이벤트가 나타나도 중복 입력 없이 단일 이벤트로 처리한다.
- 60초 내 홈 확인 실패 → NeedsUserAction, 게임/ADB/OS 프로세스 재시작은 절대 하지 않는다.
- 네코 자동 뽑기 중 날짜 변경이 나타나면 이미 승인된 소비 동작 이외의 추가 뽑기 입력을 하지 않는다.
