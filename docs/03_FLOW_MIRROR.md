**근거**: `enter_from_home`(7358~7389), `open_trial_screen_from_home`(7212~7285), `character_click`(7185~7210), `step5_6_loop`(12130~12675), `step4`(11321~11370), `_detect_mirror_card_layout`(11374~11541).

## 진입 순서
```
R01 홈
 → R02 home_trial.png (시련)
 → R03 mirror_training.png (음양의 거울 훈련)
 → R04 설정된 속성 6종 중 1개 선택
 → R05 캐릭터 1~10 좌표 선택
 → R06 dungeon_enter.png (입장)
 → R07 거울 전투/첫 카드 상태 확인
```
- 속성: `화둔`, `비둔`, `풍둔`, `토둔`, `수둔`, `뇌둔`; 정확한 이미지 매핑은 `data/screen_catalog.v0.1.json`.
- 캐릭터 기본 좌표(480x1320): `(434,456)`, `(434,510)`, `(434,564)`, `(434,619)`, `(434,673)`, `(434,727)`, `(434,781)`, `(434,835)`, `(434,889)`, `(434,943)`.
- 요일별 자동 모드를 켜면 기존 `게임 날짜=현재시각-4시간`으로 요일·속성·캐릭터를 선택. **날짜 변경 팝업은 `DateChangeFlow`가 처리하고 홈에서 새 요일로 재진입한다** (`docs/12_DATE_CHANGE.md`).
- 일부 v2.0.6 코드에는 속성 선택 중 재개 로직이 있으나 v0.1은 홈/명시된 시작 화면만 지원한다.

## 거울 전투 — 선택 반복 (기본)
1. 이전 층 클리어로 `waiting_for_next_floor=true`라면 **다음 층 `dungeon_enter`** 먼저 확인. 눌렀으면 카드 또는 거울 HUD로 실제 진입했는지 확인.
2. 카드 확인 `assets/images/image5.PNG` / 고정 카드 패널을 먼저 검사해, 카드 이미지 일부를 HUD 비기 얼굴로 잘못 판단하지 않게 한다.
3. 카드 화면이 **아닌 전투 HUD에서만** 비기 사용 조건을 확인.
4. 결과 제목 영역(화면 높이 18~33%)에서 **실패 `image8.PNG`**, 이어서 **완료 후보 `image6.PNG`**를 검사한다. `image6`는 실제로 '임무' 글자 이미지인 점을 반드시 주의; 단독 완료 확정 금지.
5. `image5` 확인 버튼과 카드 레이아웃이 식별되면 렌더링이 안정된 **두 프레임**을 확인한 뒤 카드 선택.
6. 카드 레이아웃은 4/3/2/1장 각각 카드 중심(480x1320): 4=`64,181,299,417`, 3=`84,240,397`, 2=`123,357`, 1=`240`.
7. 2장 이상은 **2장**, 1장은 **1장** 선택. 이미 선택된 카드의 초록 테두리를 확인하고 그 카드는 다시 누르지 않는다. 비기 카드가 발견되면 우선 선택 대상의 맨 앞으로 이동.
8. 필요한 카드 선택을 검증한 뒤 `(240,794)` 확인 버튼 한 번. 카드 내용/수 변화 시 새 선택 단계 인정. 불확실한 상태에선 중복 누르지 않는다.
9. 다음 선택 또는 전투로 이동. 전투 HUD의 비기 얼굴은 카드 화면에서 검사하지 않는다.

## 거울 실패 및 완료
```
[image8 실패 확인] → [image9 / 실패 확인 버튼] → [image4 재입장] → 카드/전투 확인 → R07
```
- 원본 `step5_6_loop()`는 실패 결과 처리 후 `step4()`로 반환하여 버튼을 눌러 동일 거울에 재입장한다. 실패 후 자동 '홈 복구'는 **v0.1 제외**. 재입장 버튼이 불분명하면 NeedsUserAction.
```
[완료 화면 확정] → [(239,1254) 결과 확인] → waiting_for_next_floor=true
 → [dungeon_enter] 다음 층 입장 → 카드/HUD 확인 → R07
```
- **차단 조건:** `image6.PNG`만 잡혔다고 완료 화면으로 확정하지 않는다. 실제 완료 화면의 추가 증거(확인 버튼/고유 결과 UI)를 최소 1개 확보한 후 구현. 충분한 게임 화면 자료가 없다면 명세상의 `UNVERIFIED_MIRROR_COMPLETE` 상태에 두고 버튼 클릭 금지.
- `stopAfterClear=true` 적용 위치는 소스의 완료 처리와 맞추되, **한 층 클리어와 전체 거울 종료의 의미**를 게임 화면에서 재검증해야 한다.

## 거울 임의 반복 (후순위 P1)
- 사용자 `mirrorRepeatMode=random` 선택 때만 활성화; 기본 선택 반복.
- 기존 코드의 `MIRROR_RANDOM_TAP_CYCLE`은 고정 **24입력**이며 4→3→2→1장 좌표 및 HUD 비기 좌표를 포함한다.
- 전투 중 모든 스크린샷을 포기하는 게 아니라 기존처럼 결과 화면을 각 사이클 전에 확인한다. **임의 반복은 검증되지 않은 화면에 터치를 유발할 수 있으므로** 첫 릴리스에서는 옵션 비활성으로 두고 실제 화면 테스트 후 열어도 됨.
- 터치 시퀀스 자체는 `data/workflows.v0.1.json`의 `randomTapCycle480`에 기계 판독용으로 제공.

## 선행 검증 조건
- 거울 완료 후보 `image6` 오검출률을 실제 캡처로 검증하고 완성된 완료 판별기 정의가 필요.
- 거울 선택 확인 버튼 `image5`와 실패 확인 `image9`는 모두 '확인'이므로 **허용 위치/상태**가 달라야 한다.
- 카드 수가 불확실한 상태에서 고정 좌표로 2장 찍고 넘어가지 않는다.
