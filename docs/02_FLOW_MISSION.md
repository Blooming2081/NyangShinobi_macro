# 일반 임무 흐름 (v2.0.6 순서 보존)

**근거**: `run_gui.py`의 `enter_mission_from_home`(8319~8371), `mission_worker_loop`(11163~11318), `run_one_mission`(10556~11161), `select_mission_skill`(10250~10490), `click_next_stage_if_enabled`(7903~7987), `select_configured_mission_character_preset`(8286~8317).

## 정상 진입 — 순서 바꾸지 말 것
```
M01 홈 화면
 → M02 [mission.png] 임무 버튼 클릭 → 임무 목록/진입 화면
 → M03 현재 등급 판별 (하위/상위/극의) → 다르면 해당 탭 선택
 → M04 캐릭터 프리셋 선택
 → M05 [nextStage=true일 때만] 다음 관문 오른쪽 화살표 클릭/패널 전환 확인
 → M06 [mission_enter.png] 관문으로 진입 클릭
 → M07 [새 판] 첫 인법 카드 화면 확인 및 카드 선택
 → M08 전투 관찰 루프
```
- 홈 진입 당시 이미 **임무 진입 전 화면**이면 M02를 생략 가능. 진입 가능한 상태라는 화면 근거가 있어야 한다.
- 기존 진행 중인 전투 자동 재개는 v0.1 범위 밖; `M01` 시작 조건 불일치 시 임의 조작하지 않는다.
- **초기 진입 시에는 M03→M04→M05→M06**, 성공 후 다음 판에는 **M05→M04→M06**인 v2.0.6 순서 차이를 유지한다.

## 등급 선택
- 선택 가능한 등급: `하위 임무`, `상위 임무`, `극의 임무`.
- 기존 소스는 세 탭의 최고·차순위 매칭을 비교하며 `best>=0.72`, 격차 `>=0.035`를 적용한다(장비별 재검증 필요한 **원본 기준값**).
- 목표와 같으면 클릭하지 않음. 다르면 480x1320 기준 탭 중심 `(92,240)`, `(241,240)`, `(388,240)` 비율 적용 → 선택된 탭 재확인.

## 프리셋 선택 — 핵심, 번호로 동작
- 옵션: `등급별 자동`, `프리셋 1~10`, `현재 선택 유지`.
- `등급별 자동`이면 **하위=2 / 상위=1 / 극의=10**. 이름이 아니라 *목록 내 순번*으로 선택.
- 목록 열기: 기준 좌표 `(240,1021)`; 이미 열렸으면 중복 탭하지 않는다.
- 스크롤을 목록 위로 정렬한 뒤 1~5는 해당 행, 6~10은 아래로 끝까지 스크롤하여 마지막 화면의 1~5행 선택.
- 480x1320 기준 첫 행 `(240,1062)`, 행 간격 `49px`, 표시 5행. 목록 닫힘/임무 입장 준비를 확인하고 다음 진행.
- 초기 소스에는 특세나·특로코·극의 전용 선택 헬퍼도 있으나 **최종 v2.0.6 호출은 통합 `select_configured_mission_character_preset`**. 이전 헬퍼를 중복 적용하지 않는다.

## 인법 카드 처리
- 카드 증거는 `reroll.png` 또는 카드 3장 고정 배치; 극의는 파란 3장 습득/혼합 카드 예외.
- 등급별 `assets/skill_priority/{lower_mission,upper_mission,extreme_mission}` 폴더에 등록된 이미지의 **숫자 접두부 오름차순이 우선순위**. 이미지 일치율은 '통과했는지'를 판단, 최고 점수 순은 아님.
- `__card_`(제목+카드), `__icon_`(아이콘)과 극의 전용 템플릿 종류를 구분. 일치율/ROI/스케일은 원본 감지기를 참고한 별도 데이터로 분리.
- 사용자가 이미지 등록하지 않았거나 일치하지 않으면: **하위·상위**는 `reroll` 사용 가능 시 다시뽑기, 사용 불가 시 왼쪽 카드. **극의**는 비기 카드 획득 전 19웨이브 정책에 맞게 다시 뽑기 보존, 획득 후 유효 우선카드가 없으면 남은 다시뽑기 사용, 이후 왼쪽 선택. 극의 '파란 습득 3장'은 별도 무작위 1장 선택.
- 선택 카드를 터치한 뒤 **0.5초 후 첫 반영 확인**; 기존 선택 화면이 남아 있다는 이유로 다른 카드를 무분별하게 누르지 않는다.
- 3번 비기/특수 비기 카드와 일반 인법 카드의 선택 상태는 분리 저장한다.

## 전투 프레임 판정 순서 (소스에서 확인된 순서)
1. 직전 카드 터치의 반영 대기 상태이면 입력 중지/검증.
2. 카드 화면 증거를 먼저 계산하여 룰렛 오클릭을 보호한다.
3. 룰렛 `roulette_ok`가 유효하고 카드 보호 조건에 모순이 없으면 클릭.
4. 룰렛 `roulette_skip`가 유효하면 클릭 후 결과 `roulette_ok`를 짧은 간격으로 확인.
5. 상위·극의의 룰렛 종료 직후 일정 시간 카드 오검출 방지(기존 3초 보호).
6. 카드(`reroll` 또는 카드 레이아웃/극의 습득 예외)를 감지했다면 우선순위 카드 선택.
7. 명시적 `mission_failed.png` 확인 → `mission_clear.png` 찾고 결과 닫기.
8. `mission_success_title.png` **및** `mission_clear.png` 같은 프레임 동시 확인 → 선택적 2배 보상 분기 → 새 프레임 확인 후 성공 결과 닫기.
9. 공통 `mission_clear.png`만 있으면 성공/실패를 미확정 상태로 유지.
- 결과/카드/룰렛이 동시에 오인될 수 있는 화면은 정확히 원본의 **보호 순서**를 유지하되 검사 결과를 재사용한다.
- 룰렛·비기 등 타이밍 민감 구간을 전역 3초로 강제하면 기존 기능이 깨질 수 있어 **전용 단기 관측 구간**을 별도 설계한다.

## 비기 (게임 진행 기능; P1)
- 하위/상위/극의 카드 선택 후 허용 HUD 좌표의 비기 얼굴을 판별하고 조건 충족 시 사용.
- **상위 임무** 특수 3번 비기: 카드 선택 후 `Wave 20` 종료 및 HP 임계 조건(원본 `UPPER_MISSION_SPECIAL_BIGI_HP_PERCENT`, `upper_mission_max_hp`)을 거쳐 사용.
- **극의 임무** 특수 3번 비기: 카드 선택 후 `Wave 20/20` 진입 및 진행률 기준에 따라 사용(원본 비기 모니터의 다단계 규칙). 새로운 별도 감시 스레드 상시 실행은 v0.1에 도입하지 않으며, 별도 상태 기반 센서로 구현할 것.
- 특수 비기 조건은 위와 같은 개요만으로 임의 구현하지 않는다. `reference/legacy_v206_methods/`의 관련 발췌 및 화면 검증을 먼저 수행할 것. 구현 전까지 명시적 미지원 상태로 표시.

## 결과 후 진행 — 순서 유지
```
성공 확정 + [설정 ON이고 2배 버튼이 있을 때만 광고 분기] + 새 확인 버튼 입력 + 목록 화면 확인
 → 연속 실패 횟수 초기화
 → 레벨업 팝업이 있으면 확인
 → stopAfterClear=true면 정지
 → [nextStage=true] 다음 관문 화살표 (기존 소스의 성공 후 우선 순서)
 → 프리셋 재선택
 → mission_enter → 새 판 첫 카드 → 전투
```
```
실패 확정 + 공통 확인 버튼 닫힘 확인
 → 연속 실패 +1
 → 레벨업 팝업이 있으면 확인
 → 실패 횟수 조건 충족 + '거울 전환' 설정=true라면 거울 홈 진입 흐름 시작
 → 아니면 동일 임무 홈에서 재진입
```
- **극의 예외**: 비기 사용이 확인되지 않은 실패는 기존 코드에서 거울 전환 대신 극의 재도전을 우선. 이 정책을 보존하거나 사용자 확인 뒤 명시적으로 변경.
- 임무 소모 재화 부족 팝업은 정상 상태로 처리: 새로운 임무 입장은 중단. 설정에 따라 거울 흐름으로 전환하거나 사용자가 수동으로 해결할 때까지 정지. **소진을 복구/재시작 사유로 취급하지 않는다.**
- **2배 보상 활성화 + 성공 화면에서 2배 아이콘 검출**이면 일반 확인보다 먼저 버튼 중앙을 클릭한다. 광고/보상 화면 전환을 관측하고 새 프레임에서 성공 제목+확인 버튼을 재검출한 후 `mission_clear`를 누른다. 아이콘이 없거나 설정 비활성 시 공통 확인만 누른다. 상세는 `docs/09_DOUBLE_REWARD.md`.

## 구현 시 꼭 지켜야 할 점
- 입력 성공 ≠ 게임 화면 전환 성공.
- 실패 확인을 눌렀다는 이유로 성공 횟수 증가 금지.
- 결과 확정은 '같은 프레임 성공 제목+확인 버튼' 또는 명시적 실패 제목 근거.
- `nextStage=true`여도 화살표/관문 카드가 실제 바뀌지 않았다면 입장하지 않는다.
- 현재 카드 인식이 불가능하면 무작정 왼쪽 카드 선택 금지(카드 **화면인 것**은 먼저 확인해야 한다).
