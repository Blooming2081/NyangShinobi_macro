## 미포함 (v0.1에서 만들지 않음)
- 60초 정체 감지·화면 동일성 복구, 재실행/재시작/OS 재부팅, watchdog.
- ADB 자동 재연결 및 앱플레이어 자동 실행·강제 종료, 메모리 부족 자동 복구.
- 게임 시작 화면 자동 탭·게임 실행/포그라운드 강제 변경·시작 시 모든 화면 이어하기.
- 날짜 변경 중 미확인 화면에 대한 무작위 터치 및 게임/ADB/OS 재시작 (정상적인 날짜 팝업 닫기는 **포함**).
- 장시간 로그 수집, 학습 화면 자동 저장, 복잡한 UI 통계/로그 다운로드, 스킬 편집 GUI.
- 게임 외 알 수 없는 화면 자동 조작/복구.

## 정상 진행 검증 vs 복구의 구분
- **남길 것:** 버튼 클릭 후 대상 화면 진입 확인, 카드 선택 확인, 결과 확인 후 목록 복귀 확인, 제한된 재확인.
- **뺄 것:** 오류가 발생했다고 게임/ADB/OS를 다시 실행하거나 임의의 홈 복귀 루틴을 시도하는 것.
- 판정이 불분명하면 `NeedsUserAction`으로 정지하고 현재 화면을 기록(메모리/기본 로그)한다. 자동 화면 저장은 기본 비활성.

## 실행 전제 및 첫 버전 UI
- MuMu/BlueStacks는 사용자 쪽에서 실행되어 있고, ADB 장치는 이미 연결돼 있다.
- 게임은 **홈 화면 또는 해당 모드의 명시적으로 지원되는 진입 화면**에 있어야 한다. v2.0.6처럼 현재 진행 중인 임무/다른 게임으로부터 광범위한 자동 재개는 없다.
- 사용자는 일반 임무 / 음양의 거울 / 네코 닌자 뽑기, 등급, 프리셋, 다음 관문, 완료 후 정지, 실패 시 거울 전환 기준, 거울 속성·캐릭터·반복 방식을 선택한다.
- 입력 없이 정상적으로 유지되는 카드/결과 화면은 3초 기본 검사 간격에 적합하지만, 룰렛/비기와 같은 짧은 상태에는 별도 국소 검사 규칙이 필요하다.

## 변경점 요약 (v2.0.6 → v0.1)
1. 언어/앱 구조: Python+Tkinter → C#+WPF+OpenCvSharp.
2. **게임 순서/기능적 분기는 가급적 동일**: 임무 프리셋이 선택된 후 관문 입장, 실패/성공 후 다음 단계, 거울 속성·캐릭터 선택과 카드 루프.
3. 대기 캡처: 0.22초/0.30초 기준 → 3초를 **기본값**으로 시작, 게임 이벤트 예외는 실측/회귀 테스트로 조정.
4. 자동 복구와 확장 UI 통계 화면을 제거하되 **날짜 변경 정상 처리와 이벤트 확장 구조를 포함**. 네코 닌자 뽑기와 성공 후 광고 2배 보상은 v0.1에 포함한다.
5. 이미지/버튼 확인은 그대로 필수: 단일 `mission_clear` 성공 판정 금지.

## 범위 밖 화면을 만나면
최소 로그에 `mode`, `stepId`, `screenEvidence`, `lastInput`, `reason`을 남기고 사용자의 재시작을 요청한다. 자동 무한 입력을 하지 않는다.

## 추가 기능 실행 전제
- 네코 닌자는 **별도 모드**다. 사용자가 게임에서 네코 닌자 뽑기 화면을 직접 열어놓고 시작하며 자동 메뉴 탐색/자동 종료·복구는 없다. 10회 뽑기는 게임 재화를 소비하므로 명시적 모드 선택과 언제든 중지할 수 있는 UI가 필요하다.
- 임무 광고 2배 보상은 **확정된 성공 화면에서만** 시도한다. 이미지가 없거나 설정이 꺼져 있으면 기존 공통 확인 버튼으로 바로 진행한다. 클릭이 광고 시청 완료 또는 보상 지급의 증명은 아니다.
